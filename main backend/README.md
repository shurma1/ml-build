# core-api — рабочее место оператора МФЦ

Основной сервер без GPU. Владеет Postgres+pgvector, состоянием диалога и всей
бизнес-логикой. Модели (ASR, эмбеддер, LLM) живут на арендованной видеокарте
и вызываются по HTTP через gpu-шлюз.

Контракт — `api/core-api.yaml`, схема рантайм-таблиц — `api/schema_runtime.sql`.

## Запуск

```bash
export EMB_DB="host=localhost port=5434 dbname=embeddings user=emb password=emb"
export ADMIN_SECRET="…не короче 32 символов…"     # без него процесс не стартует
export GW_BASE_URL="https://abc-10100.proxy.runpod.net"   # только первичный bootstrap
export GW_TOKEN="…"

python3 app.py                                    # :8080
```

`GW_BASE_URL` читается **один раз**, пока в `meta['gpu_gateway']` пусто. Дальше
адрес шлюза живёт в базе и меняется на ходу через `POST /v1/admin/gateway`.

Локальный стенд без видеокарты — `tools/run_dev.sh` (см. «Дублёр шлюза»).

## Правка в `embending/v2`

Ровно одна, в `dialog.py`: `DialogSearch.__init__` и `DialogSearch.embed()` —
вместо локального `SentenceTransformer` теперь HTTP-клиент к `POST /v1/embed`.
Всё остальное (RRF, резолв карточки по фасету, проверка права, выбор вопроса)
не тронуто. `git diff` по файлу укладывается в эти два метода.

**Префикс запроса здесь не добавляется** — его ставит шлюз по полю `kind`.
Цена ошибки измерена: −19 п.п. R@1, и по выдаче это не видно.

## Инварианты, которые тут защищены

1. **Право проверяется после поиска.** Услуга, на которую клиент не имеет
   права, находится и показывается со статусом `blocked` и дословной цитатой.
   Фильтра по праву на этапе retrieval нет нигде.
2. **LLM не выносит вердикт о праве** — его считает таблица предикатов;
   `POST /v1/llm/explain` только проговаривает готовый.
3. **Префикс эмбеддера — на шлюзе**, не в вызывающем коде.
4. **В `extract` уходит вся хронология, только дописывание.** Пустые сегменты
   («ага») исключены — на кэш префикса это не влияет, потому что исключение
   сохраняет дописывание.
5. **Ответ на вопрос переранжирует, а не фильтрует** (`DialogSearch.narrow`).
6. **`DialogState` только накапливает**; поле, выставленное оператором,
   помечается `pinned` и в извлечение не отдаётся вовсе.
7. **Отпечаток эмбеддера сверяется при старте.** Не совпал — `503
   index_fingerprint_mismatch` на всё, кроме `/v1/version` и админ-роута:
   иначе рассинхрон было бы нечем чинить.
8. **`search_log` пишется на каждом ходу**, плюс `opened` при открытии карточки.

## Карточка услуги

`GET /v1/services/{id}` отдаёт три слоя сразу:

* `fields` — сырые поля выгрузки как есть. Смещения подсветки считаются по ним;
* `view` — разобранный регламент: сроки, чек-лист документов, «кому положено»,
  причины отказа, правовое основание. **Каждый производный пункт несёт
  `start`/`end` в исходное поле** — без этого интерфейс не смог бы показывать
  короткую форму и подсвечивать цитату одновременно;
* `status` / `reasons` / `highlights` — вердикт о праве под факты сессии.

Разбор живёт здесь, а не на клиенте, по той же причине, по которой префикс
эмбеддера живёт на шлюзе: две реализации одного парсера расходятся молча.
Замеренная цена клиентского разбора на полном корпусе — срок у 9% карточек
вместо 87%, формула «кому положено» у 8% вместо 100%, и карточка с госпошлиной,
показанная как бесплатная.

## Деградация

| отказал | поведение |
|---|---|
| шлюз целиком | `tsvector` + `pg_trgm`, `mode: degraded_lexical` |
| только LLM | признаки из газеттира (`QueryFeatures.from_text`), накопленные факты сохраняются |
| только ASR | голос выключен, ручной ввод через `POST /turns` |
| отпечаток разъехался | `503`, обслуживание остановлено |

Сторож опрашивает `/readyz` раз в 15 с; два отказа подряд — `degraded_lexical`
и событие `degraded` во все живые сессии, ответил снова — обратно в `dense`.
Если шлюз отвалился между опросами, первый же неудавшийся вызов эмбеддера
переводит режим сам, не дожидаясь сторожа.

## Смена адреса шлюза

```bash
curl -X POST https://mfc.example.ru/api/v1/admin/gateway \
  -H "X-Admin-Secret: $ADMIN_SECRET" \
  -d '{"base_url":"https://abc-10100.proxy.runpod.net","token":"…"}'
```

Порядок строгий: сравнение секрета `hmac.compare_digest` → проверка `base_url`
(только https, для localhost можно http; без пути и параметров) → `GET /readyz`
с таймаутом 10 с (не ответил — `502`, ничего не сохраняем) → `GET /v1/models`
→ сверка отпечатка (не совпал — `409`, ничего не сохраняем; пустая `meta` —
записываем как эталонный) → запись в `meta['gpu_gateway']` → пересборка пулов
HTTP-клиентов на ходу.

Отдельно: **нечитаемый отпечаток — это не совпавший**. Если `/v1/models` не
ответил или отверг токен, а эталон в `meta` есть, адрес отклоняется с `409` и
не сохраняется. Иначе запросы начали бы кодироваться неизвестно чем при живом
индексе, а выдача осталась бы правдоподобной.

Не более 10 попыток в минуту с одного адреса. Токен не попадает ни в ответы,
ни в логи — только первые 4 символа и `***`.

Из браузера роут доступен на странице `#/gateway` рабочего места. Секрет туда
вводится руками и в сборку фронта не попадает.

`ADMIN_TRUST_PROXY=1` заставляет считать лимит по `X-Forwarded-For`. По
умолчанию выключено: заголовок ставит кто угодно, и доверие к нему по умолчанию
превратило бы лимит в декорацию. За реверс-прокси без этой переменной все
запросы придут с одного адреса, то есть лимит станет строже, а не слабее.

## Токены: какой куда

Их три, и ходят они разными путями. Ни один не должен попасть в сборку фронта:
`VITE_*` Vite подставляет в бандл, то есть отдаёт каждому, кто откроет исходники.

| токен | что закрывает | как попадает по месту |
|---|---|---|
| `API_TOKEN` | все `/v1/*` рабочего места | **подставляет реверс-прокси**, браузер его не видит |
| `ADMIN_SECRET` | `/v1/admin/*` | вводится руками на странице `#/gateway`, живёт в памяти вкладки |
| `GW_TOKEN` | доступ core-api к gpu-шлюзу | вводится на той же странице, ложится в `meta` в базе |

Рабочая схема — один источник: nginx отдаёт статику и проксирует `/v1/`,
дописывая `Authorization`. Пример: `deploy/nginx.conf`. Тогда не нужен ни CORS,
ни токен в браузере.

Два места, где это легко сломать:

* **`X-Forwarded-Host`**. Без него core-api вернёт в `ws_url` адрес апстрима,
  браузер пойдёт по нему мимо прокси — то есть мимо подстановки токена —
  и получит отказ. Либо задайте `PUBLIC_WS_BASE`.
* **WebSocket проверяется отдельно.** Middleware объявлено для scope «http»
  и на рукопожатие не распространяется: без явной проверки HTTP оказывался
  закрыт, а поток событий — открыт всем, кто знает идентификатор сессии.
  Токен принимается из заголовка (его ставит прокси) или из `?token=`
  для прямого подключения.

В разработке проще без `API_TOKEN`: vite и core-api на разных портах, адрес
задаётся `VITE_API_BASE`, а порт фронта добавляется в `CORS_ORIGINS`.

## ПДн

`turn.text` и `fact_state.state` — расшифровка разговора. Чистятся ежесуточно
по `session.purge_after` (30 дней). Текст затирается, а строки остаются: иначе
развалилась бы нумерация реплик, по которой `search_log` связан с ходом диалога.
`search_log` прямой речи не содержит и переживает чистку.

## Дублёр шлюза

`tools/stub_gateway.py` — **не продакшн**. Повторяет сетевое поведение шлюза,
но за ним:

* `/v1/embed` — настоящий `mE5-large-instruct` на CPU. Поэтому приёмочные
  метрики на нём осмысленны: векторы те же, меняется только транспорт;
* `/v1/llm/*` — заглушка на газеттире и регулярках, **не языковая модель**.
  Годится проверить конвейер, но не качество извлечения;
* `/v1/asr/*` — распознавания нет, реплики берутся из `?script=`.
