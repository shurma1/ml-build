# Промпт для разработки core-api

Скопируй всё, что ниже разделителя, в качестве задания.

---

## Что за система

Поисковая система для операторов МФЦ Тульской области. Оператор и посетитель
разговаривают; система слушает разговор, понимает, за чем человек пришёл,
и держит перед оператором короткий список подходящих услуг из 732 —
с пометкой, положена ли каждая этому человеку и почему.

Ключевое требование заказчика: **даже если услуга клиенту не подходит, система
обязана её найти и обоснованно объяснить причину несоответствия.** Оператор
показывает посетителю не пересказ, а дословную строку регламента.

Ты реализуешь **core-api** — основной сервер без GPU. Модели живут отдельно,
на арендованной видеокарте, и вызываются по HTTP.

## Что уже существует и НЕ переписывается

### 1. Модуль поиска `embending/v2/` — готов и измерен

Чистый Python поверх PostgreSQL с pgvector. Не трогай его логику: качество
поиска (R@1 0.732, R@10 0.977 на 690 запросах) получено ценой длинной серии
замеров, и «очевидные улучшения» там уже пробовали и отвергли.

| файл | что делает |
|---|---|
| `corpus.py` | 732 карточки → 318 типов услуг, муниципалитет вынесен в фасет |
| `dialog.py` | `DialogSearch.search()` — мультизапрос, RRF, право, вопросы |
| `eligibility.py` | статус права + дословная цитата, из таблицы 363 предикатов |
| `clarify.py` | наводящий вопрос по приросту информации, без LLM |
| `facets.py` | газеттир 26 муниципалитетов |
| `extraction_schema.py` | JSON-схема фактов, `validate()`, `DialogState` |
| `branches.py` | 114 филиалов, филиал → район |
| `schema.sql` | таблицы корпуса |

**Единственная правка, которую в нём делаешь:** в `DialogSearch.__init__`
и `DialogSearch.embed()` заменить локальный `SentenceTransformer` на HTTP-клиент
к `POST /v1/embed` gpu-шлюза. Всё остальное — RRF, резолв карточки по фасету,
проверка права, выбор вопроса — остаётся как есть.

### 2. GPU-контейнер `gpu/` — готов, развёрнут отдельно

Три модели за одним портом, образ `reassel/mfc-gpu-gateway`. Сервис
**не хранит состояния и не знает бизнес-логики**: ни сессий, ни диалогов,
ни корпуса услуг. Арендованная машина может быть вытеснена в любую минуту —
потеря шлюза обязана быть деградацией, а не порчей данных.

| эндпойнт | назначение |
|---|---|
| `WS /v1/asr/stream` | PCM s16le 16 кГц вверх, распознанные реплики вниз |
| `POST /v1/asr/transcribe` | файл целиком, для регрессов |
| `POST /v1/embed` | `{texts, kind: query\|passage}` → векторы 1024 + `fingerprint` |
| `POST /v1/llm/extract` | `{session_id, turns}` → провалидированные факты |
| `POST /v1/llm/ask` | `{document, question, history}` → SSE с цитатами |
| `POST /v1/llm/explain` | `{title, status, reasons}` → фраза для оператора |
| `GET /readyz` | 200, только когда прогреты все три модели |
| `GET /v1/models` | версии, `embed.fingerprint`, `vendor_sha256` |
| `GET /v1/status` | фазы загрузки, видеопамять, счётчики |

Авторизация — `Authorization: Bearer <GW_TOKEN>`. Конверт ответа:
`{"data": {...}, "meta": {"ms", "model", ...}}`, ошибки —
`{"error": {"code", "message", "retryable"}}`.

Полный контракт: `api/gpu-gateway.yaml`.

## Что строишь ты

Публичный API рабочего места оператора плюс вся бизнес-логика и всё состояние.
Контракт уже описан в `api/core-api.yaml` — реализуй его. Схема рантайм-таблиц:
`api/schema_runtime.sql`.

### Стек

* Python 3.12, FastAPI, uvicorn, `psycopg` 3 (async), `pgvector`
* PostgreSQL 17 + pgvector 0.8 + `pg_trgm`
* `httpx` для вызовов шлюза, WebSocket через FastAPI
* Никаких ORM: запросы в `v2/` написаны на чистом SQL, не переписывай их

### Основные эндпойнты

```
POST   /v1/sessions                    открыть сессию: {branch_id, operator_id}
WS     /v1/sessions/{id}/stream        аудио вверх, события вниз
POST   /v1/sessions/{id}/turns         ручной ввод реплики
POST   /v1/sessions/{id}/answers       ответы на наводящие вопросы
POST   /v1/sessions/{id}/facts         правка фактов оператором + закрепление
POST   /v1/sessions/{id}/close         исход: какую услугу выбрали
GET    /v1/sessions/{id}               снимок для восстановления UI
POST   /v1/search                      разовый поиск без сессии
GET    /v1/services/{id}               карточка + смещения подсветки
POST   /v1/services/{id}/ask           вопрос по документу, проксируется в SSE
GET    /v1/branches                    справочник филиалов
GET    /v1/version                     версии, отпечаток, режим работы
```

События вниз по WebSocket: `session.ready`, `transcript.utterance`,
`state.updated`, `results.updated`, `degraded`, `error`.

### Обработка одного хода диалога

```
кадр PCM от браузера
  → проксируется в WS /v1/asr/stream шлюза
  → пришла реплика → записать в turn, отдать transcript.utterance
  → ratelimit.is_empty_segment() — «ага», «понятно» пропускаем
  → POST /v1/llm/extract со ВСЕМИ репликами сессии в хронологии
  → DialogState.update() — монотонное слияние, pinned-поля не трогаются
  → записать fact_state, отдать state.updated
  → QueryFeatures.from_llm() → DialogSearch.search()
  → записать search_log, отдать results.updated
```

### Роут смены адреса GPU-сервера

Отдельная задача, важная практически: арендованный под получает новый адрес
при каждом пересоздании, и перенастраивать сервер через переменные окружения
с перезапуском — неудобно.

```
POST /v1/admin/gateway
X-Admin-Secret: <ADMIN_SECRET>
{"base_url": "https://abc-10100.proxy.runpod.net", "token": "…"}
```

Порядок действий, строго:

1. Сравнить секрет через `hmac.compare_digest` — сравнение за константное время,
   а не `==`.
2. Проверить `base_url`: схема только `https` (либо `http` для `localhost`),
   без пути и параметров запроса.
3. `GET {base_url}/readyz` с этим токеном, таймаут 10 с. Не ответил — `502`,
   ничего не сохранять.
4. `GET {base_url}/v1/models`, взять `embed.fingerprint`.
5. Сверить с `meta['embed_fingerprint']`. **Не совпало — `409`, не сохранять.**
   Исключение: если в `meta` пусто (индекс ещё не строился), сохранить и записать
   отпечаток как эталонный.
6. Сохранить в `meta['gpu_gateway']`: `{base_url, token, fingerprint, updated_at}`.
   Именно в БД, а не в память: настройка обязана пережить перезапуск процесса.
7. Пересоздать пул HTTP-клиентов на новый адрес **без рестарта процесса**.
8. Ответить `{ok, ready, models, latency_ms, fingerprint_match}`.

```
GET  /v1/admin/gateway         текущая конфигурация, токен замаскирован
POST /v1/admin/gateway/check   принудительная проверка живости
```

Требования безопасности:

* `ADMIN_SECRET` из окружения, не короче 32 символов; **процесс не стартует,
  если переменная не задана** — молчаливый дефолт здесь недопустим.
* Не более 10 попыток в минуту с одного адреса, дальше `429`.
* Токен шлюза никогда не попадает ни в логи, ни в ответы целиком —
  только первые 4 символа и `***`.
* Роут скрыт из публичной схемы: `include_in_schema=False`.

### Слежение за шлюзом

Фоновая задача раз в 15 секунд: `GET /readyz`. Два отказа подряд — режим
`degraded_lexical` и событие `degraded` во все активные сессии. Ответил снова —
обратно в `dense`.

## Инварианты. Нарушение каждого ломает продукт молча

1. **Право проверяется ПОСЛЕ поиска, никогда вместо него.** Отфильтрованная
   на этапе retrieval услуга теряется навсегда, а оператору нужно уметь сказать
   «услуга есть, но вам не положена вот по этой строке регламента».

2. **LLM не выносит вердикт о праве, а только проговаривает готовый.**
   Измерено на этом корпусе: 14% самопротиворечий, 17% ложных отказов,
   2.7 с на услугу. Вердикт считает таблица предикатов.

3. **Префикс эмбеддера не добавляй.** Его ставит шлюз по полю `kind`.
   Цена ошибки перемерена: −0.7…−1.0 п.п. R@1, и заметить это по выдаче невозможно. Цифра −19 п.п., стоявшая здесь раньше, относится к другому замеру (Giga-480M на плоском индексе из 732 карточек, `embending/RESULTS.md`). На нынешней конфигурации рассогласование стоит −0.7…−1.0 п.п. R@1, то есть лежит в доверительном интервале. Инвариант это не отменяет: он стоит дёшево, а по выдаче рассогласование не видно.

4. **Реплики в `/v1/llm/extract` — вся хронология, только дописывание.**
   Не суммаризируй, не обрезай окно, не переупорядочивай. На этом держится
   кэш префикса (префилл падает в 40 раз) и устойчивость модели.

5. **Ответ на наводящий вопрос переранжирует, а не фильтрует.** Жёсткий фильтр
   измерен: 0.775 против 0.810 — он выбрасывает цель, если у неё признак
   просто не заполнен.

6. **`DialogState` только накапливает.** Молчание модели не отменяет ранее
   найденный факт. Поле, выставленное оператором вручную, помечается `pinned`
   и извлечением не перезаписывается.

7. **Отпечаток эмбеддера сверяется при старте.** Не совпал — `503
   index_fingerprint_mismatch`, а не «поищем как-нибудь».

8. **`search_log` пишется на каждом ходу.** Пара «признаки диалога → услуга,
   которую оператор в итоге открыл» — это единственный способ узнать реальное
   качество: все нынешние метрики получены на синтетике.

## Подсветка фактов в карточке

Не задача для LLM. Каждый из 363 предикатов несёт дословную цитату, и при
генерации таблицы предикат отбрасывался, если цитата не встречалась в исходнике
буквально. Значит подсветка — это поиск подстроки:

```json
{"field": "serviceRecipients", "start": 120, "end": 180,
 "kind": "blocking|matching|unknown|term|payment", "reason": "услуга для категории: СВО"}
```

`blocking` — условие нарушено; `matching` — выполнено фактом о клиенте;
`unknown` — условие есть, факта нет; `term` и `payment` — срок и плата
из `canon.term_days` и `canon.is_free`.

## Деградация

| отказал | поведение | что видит оператор |
|---|---|---|
| шлюз целиком | поиск на `tsvector` + `pg_trgm`, `mode: degraded_lexical` | «распознавание недоступно, вводите текст» |
| только LLM | признаки из газеттира, `QueryFeatures.from_text()` | список беднее, вопросы работают |
| только ASR | голос выключен, ручной ввод | плашка о микрофоне |
| отпечаток разъехался | `503`, обслуживание остановлено | «индекс собран другой моделью» |

## Персональные данные

`turn.text` и `fact_state.state` — расшифровка разговора с посетителем.
Ежесуточное задание чистит их по `session.purge_after` (30 дней по умолчанию).
`search_log` прямой речи не содержит — только признаки, ранги и статусы —
и переживает чистку.

## Критерии приёмки

1. `python3 v2/eval/acceptance.py` — 22 проверки — проходит через новый
   HTTP-путь эмбеддинга без правок самих проверок.
2. Метрика на 690 запросах из `eval/citizen_queries.jsonl` не хуже
   **R@1 0.732, R@10 0.977** — то есть замена эмбеддера на сетевой ничего
   не сломала.
3. Диалог из `eval/dialogs.jsonl` проходит целиком: реплики → факты →
   поиск → вопросы, состояние накапливается монотонно.
4. Смена адреса шлюза через `/v1/admin/gateway` работает без перезапуска
   процесса; неверный секрет, мёртвый адрес и чужой отпечаток отклоняются
   с разными кодами.
5. При остановленном шлюзе поиск отвечает в режиме `degraded_lexical`,
   а не пятисоткой.
6. Токен шлюза отсутствует в логах при включённом уровне `DEBUG`.
